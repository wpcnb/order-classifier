# 绿茵传奇经典版 · 足球模拟平衡方案 v4.1

适用网页：`https://wpcnb.github.io/order-classifier/`（仓库根目录 `index.html`）。
独立新版 `football-legacy/` 继续保留独立存档，目前已同步增加累计奖杯面板。

## 发现并修复的问题

**旧赛制：** 个人进球每场按乘法叠加，数值上容易超过每场2球；球队模拟得分偏高；球员每周训练常固定加2到3点，前几个赛季某些属性很快100；金球奖评选未对所有候选人使用完全一致的权重。这些原因导致长期职业生涯夸张。

**已应用的重平衡：**
- 球队比分：采用受双方实力差、主客场因素与随机波动影响的泊松进球模型；未来比赛不会固定“2～5球起步”。
- 玩家进球：先生成球队进球，再基于位置、射门、能力、状态和关键决策生成个人进球，并限制玩家进球不超过球队总进球；助攻同理。
- 其他球队：同样使用低均值的泊松模型，避免AI球队场场四球、积分失真。
- AI球星：赛季出场、进球和助攻发生概率按位置与能力调整；不再所有球星每轮必出场。
- 训练与成长：能力提升改为累积训练经验、年龄成长速度递减；一键模拟按位置权重自动选择合适的专项训练，潜力封顶。
- 金球奖：统一考虑当赛季出场、进球、助攻、评分、能力、团队荣誉；100名记者按15/12/10/8/7/5/4/3/2/1给分，总分6700，同分按高位选票比较；旧届评选结果原样保留。
- 金靴奖：需要达到同联赛AI竞争者实际射手榜的最高进球数，而不是固定“10球就拿金靴”。
- UI：生涯金球奖、金靴奖、赛季最佳球员、欧冠冠军、欧联冠军、全部奖杯逐项累计；金球奖新增逐年排名与票分；进球/助攻赛季走势图。
- 旧存档保护：自动读取旧的 `green-legend-v2` 键，**不会强制抹除既有1900球或4座奖杯**。发现历史异常时，在“传奇档案”主动点击“历史校准”，页面显示校准前后差异并要求再次确认；保留原始历史统计作为存档内备份，也可一键恢复。已取得的金球奖数量不会凭空增加或减少。

## 校准原则

经典版球员位置 ST/LW/CM/CB/GK 分别有不同个人进球与助攻的合理上限。历史记录中只保存赛季汇总，**没有完整逐场个人进球日志**；因此旧季重平衡按出场次数做上限校准，不声称重建当年真实逐场比分，不会未经用户确认修改过去成绩。

例如，测试虚拟旧档“边锋800场1900球4金球奖”：自愿校准后约800场560球4金球奖；原1900球总数保存在 `oldStatsBackup` 中，可恢复。

## 开源项目设计参考（**借鉴理念，未复制第三方源代码和素材**）

1. **Career Legend**（MIT）：浏览器生涯、青训、关键时刻、金球奖、国家队和多联赛理念。https://github.com/RandomProjects1234/career-legend
2. **Openfoot Manager**（GPL-3.0）：事件驱动比赛、长线训练、教练、转会、持久化的系统设计。其GPL代码**没有**直接嵌入本站。https://github.com/openfootmanager/openfootmanager
3. **Agentic FC**（MIT）：让随机数、比赛事件和输入可回放，使用场景种子校准长期比赛平衡。https://github.com/gaemi/agentic-fc
4. **Global Soccer Manager**（Apache-2.0）：实力、战术与运气三者结合、双方有主客场差异。https://github.com/ecrou-exact/Global-Soccer-Manager
5. **Soccer-xG-Simulator**：使用泊松分布与蒙特卡洛模拟足球比分的概念参考。https://github.com/arya-chak/Soccer-xG-Simulator
6. **OpenFoot**：浏览器优先、用户数据库与扩展模式的产品方向。https://openfoot.app/

## 仍需深挖的地方

- 现在世界其他球员并非按整套11人真实阵容逐场分配所有进球，离FM的完整模拟尚有距离。
- 正式国家队赛事、欧战与国内杯赛的球员个人数据和国际/国内多奖项仍须加强统一账本。
- 比赛画面尚未达到EA FC/eFootball实时3D动作水平，也不能合法直接使用商业足球游戏的素材与数据库。
- 继续升级前应保留旧存档格式向后兼容，禁止未经确认重写历史积分、夺冠和金球奖记录。
